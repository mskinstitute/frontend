# Static (SSG) vs Dynamic (SSR) Rendering & generateStaticParams

Next.js automatically determines whether a route should be rendered statically at build time (**Static Site Generation - SSG**) or dynamically on every user request (**Server-Side Rendering - SSR**). For dynamic routes with parameters, **`generateStaticParams`** unlocks blazing static performance.

---

## 1. Static vs Dynamic Rendering

- **Static Rendering (Default):** Routes are rendered into HTML at build time (`npm run build`) or during background revalidation. Resulting files are cached globally on edge CDNs for near-zero millisecond response times.
- **Dynamic Rendering:** Routes are rendered on the server for each individual user request. Automatically triggered when using **Dynamic Functions** (`cookies()`, `headers()`, `searchParams`).

---

## 2. Dynamic Functions Triggering Dynamic Rendering

If a component uses information specific to an incoming user request, Next.js automatically opts that route into Dynamic Rendering:
- `cookies()` from `next/headers`
- `headers()` from `next/headers`
- Accessing `searchParams` in `page.tsx`

```tsx
import { cookies } from 'next/headers';

export default async function UserCartPage() {
  const cookieStore = await cookies();
  const cartToken = cookieStore.get('cart_token'); // Dynamic function forces SSR!

  return <div>Your Cart Token: {cartToken?.value}</div>;
}
```

---

## 3. Prerendering Dynamic Routes with `generateStaticParams`

For dynamic paths like `app/courses/[slug]/page.tsx`, Next.js doesn't know what slugs exist at build time unless you specify them. **`generateStaticParams`** queries your database during build time to generate static HTML pages for all known slugs!

```tsx
// app/courses/[slug]/page.tsx
import { getAllCourseSlugs, getCourseBySlug } from '@/lib/courses';
import { notFound } from 'next/navigation';

// 1. generateStaticParams: runs at build time on the server
export async function generateStaticParams() {
  const slugs = await getAllCourseSlugs(); // e.g. ['tailwind-css', 'nodejs-backend']

  return slugs.map((slug) => ({
    slug: slug
  }));
}

// 2. Page Component: statically generated for all returned slugs!
export default async function CourseDetailPage({
  params
}: {
  params: Promise<{ slug: string }>;
}) {
  const { slug } = await params;
  const course = await getCourseBySlug(slug);

  if (!course) notFound();

  return (
    <div className="max-w-4xl mx-auto py-10">
      <h1 className="text-4xl font-bold">{course.title}</h1>
      <p className="mt-4 text-slate-600">{course.description}</p>
    </div>
  );
}
```

---

## 4. The Dynamic Params Option (`dynamicParams`)

Control what happens when a user visits a dynamic slug that was **NOT** generated at build time:

```typescript
// true (default): Next.js will render the new slug dynamically on demand and cache it!
// false: Next.js returns an immediate 404 for any slug not returned by generateStaticParams.
export const dynamicParams = true;
```

# Multiple Choice Questions

### 1. What does the `generateStaticParams` function do in dynamic routes?
A. It compiles JavaScript into CSS.
B. It defines the list of route parameter values to be prerendered statically into HTML at build time.
C. It generates random user passwords.
D. It resets the database before building.
**Answer:** B
**Explanation:** `generateStaticParams` provides Next.js with an array of parameters to statically pre-render dynamic routes during `npm run build`.
---

### 2. What happens if a component uses `cookies()` or `headers()` from `next/headers`?
A. The build fails with a type error.
B. Next.js automatically switches that route from Static Rendering to Dynamic Rendering (SSR) for every incoming request.
C. The cookies are cleared.
D. The page is permanently converted into a client component.
**Answer:** B
**Explanation:** Calling dynamic functions like `cookies()` requires inspecting the live incoming HTTP request, forcing Next.js to render the page dynamically.
---

### 3. What does setting `export const dynamicParams = false;` in a page do?
A. It disables all parameters.
B. It returns a 404 page for any route segment that was not pre-generated by `generateStaticParams`.
C. It converts numbers into strings.
D. It forces client-side hydration.
**Answer:** B
**Explanation:** `dynamicParams = false` restricts visits strictly to the paths pre-rendered at build time, returning a 404 for unknown parameters.
---

### 4. What is the primary advantage of Static Site Generation (SSG) over Dynamic Server-Side Rendering (SSR)?
A. Static HTML files can be cached on worldwide Edge Content Delivery Networks (CDNs), delivering instant response times with minimal server load.
B. Static sites cannot be hacked.
C. Static sites do not use HTML.
D. Static rendering requires no build step.
**Answer:** A
**Explanation:** Static pages are served directly from global CDN edge caches without executing backend server code on every request.
---

### 5. Which symbol in the `npm run build` output indicates that a route has been statically pre-rendered?
A. A circle `○` (or `●` for SSG/Prerendered)
B. A red cross `✗`
C. A question mark `?`
D. An exclamation mark `!`
**Answer:** A
**Explanation:** The Next.js build terminal output uses circle icons (`○` for static and `●` for SSG/ISR) to indicate statically prerendered routes.
