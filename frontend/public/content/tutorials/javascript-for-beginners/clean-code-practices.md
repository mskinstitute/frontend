# Clean Code Practices in JavaScript

Writing code that works is only the baseline requirement. Writing clean, expressive, and maintainable code is what makes you an indispensable software engineer. Here are the core clean code principles applied to modern JavaScript.

---

## 1. Meaningful & Intent-Revealing Names

Variable and function names should answer three questions: **Why does it exist? What does it do? How is it used?**

```javascript
// ❌ BAD: Cryptic and meaningless
const d = 86400;
const u = getUsers();
function chk(a, b) { return a > b; }

// ✅ CLEAN: Self-documenting
const SECONDS_PER_DAY = 86400;
const activeUsersList = getActiveUsers();
function isUserEligibleForDiscount(userAge, minimumAge) {
  return userAge >= minimumAge;
}
```

---

## 2. Functions Should Do ONE Thing Well (Single Responsibility)

A function should have a single responsibility. If a function validates input, writes to a database, and formats an email, it should be split into three modular functions:

```javascript
// ❌ BAD: God Function doing 3 unrelated tasks
function handleUserSignup(userData) {
  // 1. Validating password...
  // 2. Inserting into database...
  // 3. Sending welcome email...
}

// ✅ CLEAN: Modular, testable functions
function validateUserCredentials(credentials) { /* ... */ }
function saveUserToDatabase(user) { /* ... */ }
function sendWelcomeEmail(userEmail) { /* ... */ }
```

---

## 3. Limit Function Arguments (Max 2 or 3)

When a function takes 5 or 6 arguments, calling it is error-prone:
```javascript
// ❌ BAD: What order do arguments go in?
createUser("Sumit", "Sharma", "sumit@msk.com", "Admin", true, "New Delhi");

// ✅ CLEAN: Pass a single configuration object with destructuring!
createUser({
  firstName: "Sumit",
  lastName: "Sharma",
  email: "sumit@msk.com",
  role: "Admin",
  isActive: true,
  city: "New Delhi"
});
```

---

## 4. Avoid Magic Numbers and Magic Strings

A **magic number** is a hardcoded numerical value with no clear meaning:

```javascript
// ❌ BAD: What does 86400000 mean?
setTimeout(restartServer, 86400000);

// ✅ CLEAN: Assign to a named constant!
const MILLISECONDS_IN_24_HOURS = 24 * 60 * 60 * 1000;
setTimeout(restartServer, MILLISECONDS_IN_24_HOURS);
```

---

## 5. Favor Immutability & Modern Array Methods

Instead of mutating arrays with index-based loops and temporary variables, use functional methods (`map`, `filter`, `reduce`):

```javascript
// ❌ BAD: Imperative mutation with temporary array
const highScores = [];
for (let i = 0; i < scores.length; i++) {
  if (scores[i] >= 80) {
    highScores.push(scores[i] * 1.1);
  }
}

// ✅ CLEAN: Declarative, readable transformation
const highScores = scores
  .filter(score => score >= 80)
  .map(score => score * 1.1);
```

## Practice Quiz

### Q1: According to the Single Responsibility Principle (SRP), what should a function do?
- A) As many things as possible to save lines of code
- B) Perform one single task or unit of logic exceptionally well
- C) Always contain at least 100 lines of code
- D) Handle both frontend and backend tasks
**Answer:** B
**Explanation:** Single Responsibility states that a function should do one thing, do it well, and do it only.

### Q2: What is a "magic number" in programming?
- A) A prime number
- B) A hardcoded numerical value without clear named context that confuses readers
- C) A random number generated by Math.random()
- D) A negative float
**Answer:** B
**Explanation:** Magic numbers are unexplained literals in code; replacing them with named constants improves readability and maintainability.

### Q3: Why is passing a single destructured object preferable to having 6 individual positional function arguments?
- A) Object arguments don't depend on strict parameter order and make function calls self-documenting
- B) JavaScript only allows up to 3 arguments
- C) Objects execute twice as fast
- D) It avoids typing curly braces
**Answer:** A
**Explanation:** Named parameters via objects prevent argument-order mistakes and allow easy omission of optional arguments with defaults.

### Q4: Which naming convention is recommended for boolean variables to make them self-documenting?
- A) Suffix with `_num`
- B) Prefix with auxiliary verbs like `is`, `has`, `can`, or `should` (e.g. `isLoading`, `hasPermission`)
- C) Use ALL CAPS
- D) Single letters like `b`
**Answer:** B
**Explanation:** Prefixes like `isLoggedIn` or `hasSubscription` make conditional checks read naturally like English sentences.

### Q5: What does the DRY software engineering principle stand for?
- A) "Do Repeat Yourself"
- B) "Don't Repeat Yourself" (eliminate duplicate logic through reusable abstractions)
- C) "Data Routing Year"
- D) "Deploy React Yesterday"
**Answer:** B
**Explanation:** DRY stands for "Don't Repeat Yourself", emphasizing that every piece of knowledge or logic must have a single, authoritative representation in a codebase.
