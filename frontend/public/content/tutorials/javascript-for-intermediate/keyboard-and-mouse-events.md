# Keyboard & Mouse Events in Modern JavaScript

Capturing user input through keyboards, mice, and pointer devices is essential for creating interactive web apps like search dropdowns, modal windows, drag-and-drop interfaces, and gaming loops.

---

## 1. Keyboard Events: keydown, keyup, and key

### Event Types
- `keydown`: Fires immediately when a key is pressed down. Repeats if held down.
- `keyup`: Fires when the key is released.
- *(Note: `keypress` is deprecated and should not be used in modern code).*

### Key Properties: key vs. code

```javascript
window.addEventListener('keydown', (event) => {
  console.log('Key:', event.key);   // Actual character printed (e.g. 'Enter', 'a', 'A', 'Escape')
  console.log('Code:', event.code); // Physical hardware key code (e.g. 'KeyA', 'Enter', 'Space')
  console.log('Modifier keys:', {
    ctrl: event.ctrlKey,
    alt: event.altKey,
    shift: event.shiftKey,
    meta: event.metaKey // Command on Mac, Windows key on PC
  });
});
```

```
Physical Keyboard Key: [ 'A' key ]
  • When Shift is NOT pressed:  key = 'a',  code = 'KeyA'
  • When Shift IS pressed:      key = 'A',  code = 'KeyA'
```

### Implementing Keyboard Shortcuts (Modal Escape)

```javascript
document.addEventListener('keydown', (event) => {
  // Close modal on 'Escape'
  if (event.key === 'Escape') {
    const activeModal = document.querySelector('.modal.open');
    if (activeModal) activeModal.classList.remove('open');
  }

  // Save shortcut: Ctrl + S or Cmd + S
  if ((event.ctrlKey || event.metaKey) && event.key.toLowerCase() === 's') {
    event.preventDefault(); // Prevent browser 'Save Webpage' dialog
    saveDocument();
  }
});
```

## 2. Mouse Events: click, dblclick, mousedown, mouseup

```javascript
const box = document.querySelector('.interactive-box');

box.addEventListener('mousedown', (e) => {
  // e.button: 0 = Main (Left), 1 = Auxiliary (Middle), 2 = Secondary (Right)
  if (e.button === 0) {
    console.log('Left mouse button pressed');
  }
});

box.addEventListener('contextmenu', (e) => {
  e.preventDefault(); // Prevents default browser right-click menu
  showCustomContextMenu(e.clientX, e.clientY);
});
```

## 3. Mouse Coordinate Systems: client, page, and screen

```
  ┌──────────────────────────────────────────────┐  Screen (e.screenX/Y)
  │ Monitor Display Boundary                     │
  │   ┌────────────────────────────────────────┐ │
  │   │ Browser Window Viewport                │ │  Client (e.clientX/Y)
  │   │ (e.clientX = relative to viewport)     │ │
  │   │   ┌──────────────────────────────────┐ │ │
  │   │   │ Rendered Web Page Document       │ │ │  Page (e.pageX/Y)
  │   │   │ (e.pageX = includes scroll offset│ │ │
  │   │   └──────────────────────────────────┘ │ │
  │   └────────────────────────────────────────┘ │
  └──────────────────────────────────────────────┘
```

```javascript
document.addEventListener('mousemove', (e) => {
  // Coordinates relative to visible viewport window
  const clientX = e.clientX;
  const clientY = e.clientY;

  // Coordinates relative to whole HTML document (includes scroll position)
  const pageX = e.pageX;
  const pageY = e.pageY;

  // Update a custom cursor position
  customCursor.style.transform = `translate3d(${clientX}px, ${clientY}px, 0)`;
});
```

## 4. mouseenter / mouseleave vs. mouseover / mouseout

This difference is critical for hover menus and tooltips:
- `mouseover` and `mouseout`: **Bubble up** through child elements. Moving over a child inside the container fires additional events!
- `mouseenter` and `mouseleave`: **Do NOT bubble**. They trigger strictly when entering or leaving the target element boundary.

```javascript
const dropdown = document.querySelector('.dropdown');

// Clean hover behavior without child flickering
dropdown.addEventListener('mouseenter', () => dropdown.classList.add('active'));
dropdown.addEventListener('mouseleave', () => dropdown.classList.remove('active'));
```

## 5. Pointer Events: The Modern Unified Standard

Pointer Events unify Mouse, Touch, and Stylus/Pen interactions into a single API:

```javascript
const canvas = document.querySelector('#drawing-canvas');

canvas.addEventListener('pointerdown', (e) => {
  console.log(`Input Device: ${e.pointerType}`); // 'mouse', 'touch', or 'pen'
  console.log(`Pressure: ${e.pressure}`);        // Stylus pressure level (0.0 to 1.0)
});
```

## Practice Quiz

### Q1: Which property should you check to inspect the actual semantic character generated by a key press?
- A) event.keyCode
- B) event.code
- C) event.key
- D) event.which
**Answer:** C
**Explanation:** `event.key` provides the semantic character representation (e.g. 'Enter', 'Escape', 'a', 'A'), whereas `event.code` identifies the physical key on the keyboard.

### Q2: How do mouseenter and mouseleave differ from mouseover and mouseout?
- A) mouseenter and mouseleave do not bubble through child elements
- B) mouseover works only on touchscreens
- C) mouseleave is fired when the user presses Enter
- D) mouseenter requires double clicking
**Answer:** A
**Explanation:** `mouseenter` and `mouseleave` do not bubble, making them ideal for dropdown menus and tooltips without erratic flickering when hovering over nested children.

### Q3: What coordinate property represents mouse position relative to the visible browser viewport?
- A) event.screenX / event.screenY
- B) event.pageX / event.pageY
- C) event.clientX / event.clientY
- D) event.offsetX / event.offsetY
**Answer:** C
**Explanation:** `clientX` and `clientY` measure the pointer position relative to the top-left corner of the currently visible viewport regardless of page scrolling.

### Q4: How do you prevent the standard browser context menu from appearing upon right-click?
- A) e.target.removeMenu()
- B) event.preventDefault() inside a 'contextmenu' event listener
- C) return false inside a 'keyup' listener
- D) e.stopPropagation() inside 'mouseenter'
**Answer:** B
**Explanation:** Listening to the `contextmenu` event and executing `event.preventDefault()` suppresses the native operating system right-click context menu.

### Q5: What is the main advantage of the Pointer Events API (pointerdown, pointermove) over traditional Mouse Events?
- A) It runs directly inside CSS files
- B) It provides a unified API handling mouse, touch screens, and stylus inputs simultaneously
- C) It prevents all network latency
- D) It does not require addEventListener
**Answer:** B
**Explanation:** Pointer Events unify mouse, touch, and stylus pen inputs under a single set of event handlers with rich hardware metadata (pressure, tilt, contact area).
