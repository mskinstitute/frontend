# Flask-WTF Setup & CSRF Token Protection

Handling HTML form submissions safely is one of the most critical security aspects of web development. Naive form handling without validation exposes applications to SQL injection, malicious scripts, and **Cross-Site Request Forgery (CSRF)** attacks.

The **Flask-WTF** extension integrates **WTForms** with Flask, providing declarative form classes, field type casting, built-in input sanitization, and automatic CSRF token protection.

---

## 1. What is Cross-Site Request Forgery (CSRF)?

In a CSRF attack, an attacker tricks a victim's authenticated browser into executing unwanted actions on a trusted website:

```
1. User logs into your bank or portal -> Session cookie stored in browser.
2. User visits a malicious third-party website in another tab.
3. Malicious site triggers a background POST request to your portal:
   <form action="https://yourbank.com/transfer" method="POST">
       <input type="hidden" name="amount" value="50000">
       <input type="hidden" name="to_account" value="attacker_id">
   </form>
4. Because cookies are sent automatically by the browser, the server processes the request!
```

### The Synchronizer Token Defense:
To prevent CSRF, Flask-WTF generates a cryptographically unique, unpredictable token bound to the user's active session. When submitting a form, the client must transmit this token. If the token is missing or mismatched, Flask immediately aborts the request with an HTTP **400 Bad Request (CSRF Token Missing or Invalid)**.

## 2. Installing and Configuring Flask-WTF

Install the extension:

```bash
pip install flask-wtf
```

Flask-WTF **requires** a secret key configured on the application to cryptographically sign CSRF tokens:

```python
import os
from flask import Flask
from flask_wtf.csrf import CSRFProtect

app = Flask(__name__)

# Essential: Must be a strong, unpredictable random string
app.config["SECRET_KEY"] = os.environ.get("SECRET_KEY", "dev-fallback-key-9f42c7104b2a")

# Enable global CSRF protection across all POST/PUT/PATCH/DELETE requests
csrf = CSRFProtect(app)
```

## 3. Rendering CSRF Tokens in HTML Forms

When rendering raw HTML forms without WTForms form classes, inject the CSRF token using `csrf_token()`:

```html
<form method="POST" action="/submit-feedback">
    <!-- Hidden CSRF security input -->
    <input type="hidden" name="csrf_token" value="{{ csrf_token() }}">

    <div class="mb-4">
        <label for="feedback">Your Feedback:</label>
        <textarea id="feedback" name="feedback" required></textarea>
    </div>

    <button type="submit">Submit Feedback</button>
</form>
```

## 4. Protecting AJAX and Fetch API Requests

For Single Page Apps or JavaScript `fetch()` requests, pass the CSRF token via the `X-CSRFToken` HTTP header:

```html
<!-- Inject CSRF token into HTML meta tag -->
<meta name="csrf-token" content="{{ csrf_token() }}">

<script>
const csrfToken = document.querySelector('meta[name="csrf-token"]').getAttribute('content');

async function postComment(commentText) {
    const response = await fetch('/api/comments', {
        method: 'POST',
        headers: {
            'Content-Type': 'application/json',
            'X-CSRFToken': csrfToken  // Verified automatically by CSRFProtect!
        },
        body: JSON.stringify({ comment: commentText })
    });
    return await response.json();
}
</script>
```

---

## 5. Exempting Webhooks with `@csrf.exempt`

External machine-to-machine services (such as Stripe payment webhooks or GitHub Actions webhooks) cannot provide a browser session CSRF token. Exempt specific endpoints using the `@csrf.exempt` decorator:

```python
@app.route("/webhooks/stripe", methods=["POST"])
@csrf.exempt
def stripe_webhook():
    # Verify signature using Stripe cryptographic headers instead of CSRF tokens
    return {"status": "Webhook received"}, 200
```

## Practice Quiz

### Q1: What application setting is mandatory for Flask-WTF to sign CSRF tokens?
- A) `app.config['DATABASE_URL']`
- B) `app.config['SECRET_KEY']`
- C) `app.config['CSRF_SALT']`
- D) `app.config['SESSION_TYPE']`
**Answer:** B
**Explanation:** Flask-WTF requires `app.config['SECRET_KEY']` to cryptographically sign session tokens and verify that incoming CSRF tokens were generated by the application.

### Q2: What HTTP status code does Flask-WTF return if a POST request fails CSRF verification?
- A) `200 OK`
- B) `400 Bad Request`
- C) `404 Not Found`
- D) `502 Bad Gateway`
**Answer:** B
**Explanation:** A missing, expired, or tampered CSRF token results in an HTTP 400 Bad Request response with the reason "The CSRF token is missing" or "The CSRF token is invalid."

### Q3: Which HTTP header does `CSRFProtect` inspect for AJAX / fetch requests?
- A) `Authorization`
- B) `X-CSRFToken`
- C) `X-Security-Hash`
- D) `Content-Security-Policy`
**Answer:** B
**Explanation:** By default, Flask-WTF's `CSRFProtect` inspects the `X-CSRFToken` (or `X-CSRF-Token`) HTTP request header for AJAX requests.

### Q4: Why must payment gateway webhooks (e.g. Stripe, Razorpay) be marked with `@csrf.exempt`?
- A) Because payment webhooks do not use HTTP
- B) Because automated third-party server callbacks do not possess a user browser session or CSRF token
- C) To make payments faster
- D) Because webhooks only accept GET requests
**Answer:** B
**Explanation:** Machine-to-machine webhooks originate from external cloud servers without user sessions, so they must be exempted from browser CSRF checks and verified using cryptographic HMAC signatures instead.

### Q5: How do you output the raw CSRF token value inside an HTML template?
- A) `{{ get_token() }}`
- B) `{{ csrf_token() }}`
- C) `{{ session.token }}`
- D) `{{ request.csrf }}`
**Answer:** B
**Explanation:** The `{{ csrf_token() }}` template function generates and returns the active signed CSRF token for the current session.
