# Introduction to Power BI Embedded: Architectures & Use Cases

Enterprises frequently need to deliver interactive Power BI dashboards **directly inside custom web applications, client customer portals, or corporate intranet systems** (e.g., Salesforce, SharePoint, custom React/Node.js web portals).

This capability is powered by **Power BI Embedded**.

---

## 1. The Two Core Architectural Models of Embedding

When architecting an embedded BI solution, developers must choose between two distinct identity and licensing approaches:

```
                              Power BI Embedding Architectures
                                             |
             +-------------------------------+-------------------------------+
             |                                                               |
    "User Owns Data" (Embed for Org)                                "App Owns Data" (Embed for Customers)
  - Intended for internal employees                               - Intended for external third-party clients
  - Users authenticate via corporate Microsoft 365                - Users log into custom portal (JWT / Auth0 / DB)
  - Every user MUST have a Power BI Pro/PPU license               - End-users do NOT need any Power BI license!
  - Example: Embedding an internal HR dashboard into SharePoint   - Example: A SaaS app providing billing analytics
```

---

## 2. Technical Workflow: "App Owns Data" (Customer Portal)

In customer-facing SaaS applications, requiring thousands of external clients to purchase Microsoft Power BI licenses is commercially unviable. The **App Owns Data** pattern solves this:

```
[External User] ---> Logs into Custom Web Portal (React / Angular)
                              |
                              v
                   [Backend API (Node / Python)]
                              |
                              v (Authenticates with Azure Entra ID using Service Principal)
                   [Azure Entra ID / Microsoft Graph]
                              |
                              v (Requests Embed Token with RLS identity)
                   [Power BI REST API]
                              |
                              v (Returns Embed URL + Secure Token)
                   [Web Frontend (Power BI JavaScript SDK)]
                              |
                              v
                   [Interactive Dashboard Rendered inside <iframe>]
```

### Key Components:
1. **Service Principal (App Registration):** A headless service account registered in Microsoft Entra ID with permissions to access Power BI workspace assets.
2. **Embed Token:** A time-limited, encrypted JWT token generated by your backend server granting the client browser permission to view a specific report and dataset.
3. **Power BI Client JavaScript SDK (`powerbi-client`):** The client-side npm library used to initialize, interact with, and dynamically filter the embedded iframe.

# Multiple Choice Questions

### 1. What is the fundamental difference between "Embed for your organization" and "Embed for your customers"?
A. One uses Windows and the other uses Linux
B. "Embed for your organization" requires end-users to have Power BI licenses and sign in with Entra ID; "Embed for your customers" allows external users without Power BI licenses to view reports using an application-generated Embed Token
C. "Embed for your customers" only works on mobile phones
D. There is no technical difference
**Answer:** B
**Explanation:** "Embed for your customers" (App Owns Data) utilizes a single master service principal account to generate secure embed tokens, allowing external SaaS clients to view dashboards without needing their own Microsoft licenses.

### 2. Which client-side JavaScript library is used to embed and control Power BI reports inside web applications?
A. `powerbi-client` (Power BI JavaScript SDK)
B. `react-dom`
C. `jquery-powerbi`
D. `bootstrap-embed`
**Answer:** A
**Explanation:** Microsoft provides the official `powerbi-client` npm library to embed reports, capture events, and interact with report pages programmatically via JavaScript.

### 3. What security entity in Microsoft Entra ID (Azure AD) is recommended to authenticate the backend server in an "App Owns Data" embedded architecture?
A. Personal Gmail account
B. Service Principal (Application Registration)
C. Local Windows user
D. Anonymous public access
**Answer:** B
**Explanation:** A Service Principal represents a secure non-human service identity in Azure AD, allowing automated backend systems to communicate with Power BI APIs securely without hardcoding human credentials.

### 4. Can Row-Level Security (RLS) be enforced when using "App Owns Data" embedding for external users?
A. No, RLS is disabled in embedded scenarios
B. Yes; the backend server generates the Embed Token specifying the user's identity and roles dynamically via the `EffectiveIdentity` property
C. Only if the user has an admin password
D. RLS only works in Excel
**Answer:** B
**Explanation:** When requesting an embed token via the REST API, the backend application passes an `EffectiveIdentity` object containing the user's username and RLS roles, enforcing database-level security seamlessly.

### 5. What Azure dedicated resource tier is commonly purchased to power commercial-grade Power BI Embedded applications?
A. Azure Virtual Machines
B. Power BI Embedded (A-SKU) or Fabric Capacity (F-SKU)
C. Azure Blob Storage
D. Azure DNS
**Answer:** B
**Explanation:** Azure A-SKUs (e.g., A1 to A6) or Fabric F-SKUs provide dedicated cloud compute capacity specifically for Power BI embedding, billing per hour without requiring per-user licenses.
