# Dataflows, Gateways & Scheduled Refresh in Power BI Service

In a mature enterprise, multiple departments often require the exact same core entities (e.g., standard `Dim_Customer`, `Dim_Date`, and `Dim_Product` tables). If 10 different developers write 10 separate Power Query ETL scripts connecting to the same transactional database, it creates redundant database load and conflicting business logic.

The architectural solution is **Power BI Dataflows**.

---

## 1. What is a Power BI Dataflow? (Self-Service Cloud ETL)

A **Dataflow** is Power Query running in the **Power BI Cloud**:
- Dataflows extract, clean, transform, and load data from source systems.
- The transformed tables are stored in **Azure Data Lake Storage Gen2** (or Microsoft Dataverse) as standardized Common Data Model (CDM) entities.
- Developers then connect Power BI Desktop to the Dataflow rather than the raw database!

```
Traditional Redundant ETL (Anti-Pattern):
[ERP Database] ---> Report 1 (Pulls Customers & Cleans)
[ERP Database] ---> Report 2 (Pulls Customers & Cleans)
[ERP Database] ---> Report 3 (Pulls Customers & Cleans)

Modern Centralized Architecture with Dataflows:
[ERP Database] ---> [Central Power BI Dataflow: "Corporate Dimensions"]
                           | (Cleansed, Standardized Once in Azure)
                           +---> Report 1 (Connects to Dataflow)
                           +---> Report 2 (Connects to Dataflow)
                           +---> Report 3 (Connects to Dataflow)
```

---

## 2. On-Premises Data Gateway: Bridging Cloud to Ground

When your source data resides on an internal company server (e.g., on-premises SQL Server, local file share) behind a corporate firewall:
- The Power BI cloud service **cannot** directly reach into your private network.
- You must install an **On-Premises Data Gateway**:

```
Cloud                                      Corporate Firewall
[Power BI Service] <==== Encrypted Outbound Connection (Port 443) ====> [Data Gateway] ---> [Internal SQL Server]
```

### Gateway Modes:
1. **Standard Mode (Enterprise):** Serves multiple users, multiple datasets, and supports DirectQuery and scheduled refreshes. Installed on a dedicated server.
2. **Personal Mode:** Runs only under a single user's Windows login. Shuts down when the user logs off. Not recommended for enterprise production.

---

## 3. Configuring Scheduled Refresh

1. In the Power BI Service, open your dataset's **Settings**.
2. Expand **Gateway and cloud connections** and map the dataset to your active Gateway cluster.
3. Expand **Data source credentials** and sign in.
4. Expand **Scheduled refresh**:
   - Toggle to **ON**.
   - Select frequency: **Daily** or **Weekly**.
   - Add refresh time slots (Power BI Pro supports up to **8 scheduled refreshes per day**; Premium supports up to **48 per day**).
   - Configure failure notification emails to alert the BI team if a refresh fails.

# Multiple Choice Questions

### 1. What is a primary architectural benefit of creating Power BI Dataflows?
A. They convert reports into Excel sheets
B. They centralize and reuse Power Query ETL transformations across multiple datasets, reducing source database load and establishing a single source of truth
C. They eliminate the need for a web browser
D. They automatically build visuals
**Answer:** B
**Explanation:** Dataflows allow organizations to perform ETL once and share clean, standardized tables (like a certified Date or Customer table) across dozens of downstream datasets.

### 2. What hardware/software component is required to allow the cloud Power BI Service to refresh data from an on-premises local SQL Server?
A. A USB flash drive
B. An On-Premises Data Gateway installed inside the corporate network
C. Windows Media Player
D. Bluetooth connection
**Answer:** B
**Explanation:** An On-Premises Data Gateway acts as a secure reverse-proxy bridge, establishing encrypted outbound communication between the Power BI Service and private on-premises databases.

### 3. What is the maximum number of daily scheduled refreshes allowed for a dataset in a Power BI Pro workspace?
A. 1
B. 8
C. 48
D. Unlimited
**Answer:** B
**Explanation:** Datasets hosted in standard Power BI Pro capacity support up to 8 scheduled refreshes per day, whereas Power BI Premium capacity supports up to 48 refreshes per day.

### 4. Where is the data generated by a Power BI Dataflow physically stored?
A. On the local user's Desktop
B. In Azure Data Lake Storage Gen2 managed by Microsoft (or your organization's Azure tenant)
C. In an email attachment
D. In the browser cache
**Answer:** B
**Explanation:** Dataflows store their transformed tables as structured Common Data Model (CDM) CSV or Parquet files in Azure Data Lake Storage Gen2.

### 5. Why should the "Standard Mode" Data Gateway be installed on a dedicated server rather than a developer's personal laptop?
A. Laptops do not support Microsoft software
B. If a personal laptop is closed, turned off, or disconnected from the network, all scheduled cloud data refreshes will immediately fail
C. Standard mode requires a touchscreen
D. Personal mode is faster
**Answer:** B
**Explanation:** Standard gateways must run continuously 24/7 on an always-on server to reliably execute scheduled automated refreshes outside of standard working hours.
