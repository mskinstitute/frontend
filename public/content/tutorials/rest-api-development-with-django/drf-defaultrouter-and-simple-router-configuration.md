# DRF DefaultRouter and SimpleRouter Configuration

Django REST Framework routers eliminate manual URL routing boilerplate by automatically mapping standard `ViewSet` actions to predictable RESTful URLs. Understanding the differences between **`SimpleRouter`** and **`DefaultRouter`**, customizing trailing slashes, and managing format suffixes ensures seamless API routing.

---

## 1. Comparing `SimpleRouter` vs `DefaultRouter`

| Feature | `SimpleRouter` | `DefaultRouter` |
| :--- | :--- | :--- |
| **Generates CRUD routes** | Yes (`list`, `create`, `retrieve`, `update`, `destroy`) | Yes |
| **API Root Endpoint (`/`)** | **No** (returns 404 at root) | **Yes** (Generates hyperlinked index of all endpoints) |
| **Format Suffix Patterns** | Optional manual configuration | **Automatic** (supports `.json`, `.api` suffixes) |
| **Sweet Spot** | Sub-routers or internal micro-APIs | Public API roots and browsable enterprise portals |

---

## 2. Advanced Router Configuration

```python
# api/urls.py
from django.urls import path, include
from rest_framework.routers import DefaultRouter
from .views import ProductViewSet, CategoryViewSet, OrderViewSet

# Instantiate DefaultRouter with optional trailing slash configuration
router = DefaultRouter(trailing_slash=True) # Enforces standard trailing slashes /items/

# Register viewsets
router.register(r"products", ProductViewSet, basename="product")
router.register(r"categories", CategoryViewSet, basename="category")
router.register(r"orders", OrderViewSet, basename="order")

app_name = "api_v1"

urlpatterns = [
    # Exposes API Root and all registered viewset paths
    path("", include(router.urls)),
]
```

---

## 3. The Trailing Slash Debate (`trailing_slash=False`)

By default, Django and DRF enforce trailing slashes (`/api/v1/products/`). If a client requests `/api/v1/products`, Django sends a `301 Moved Permanently` redirect to the slashed URL.

In REST APIs consumed by frontend frameworks, unexpected 301 redirects on `POST` requests can drop the request body. If your client architecture strictly avoids trailing slashes:

```python
# Disables trailing slash requirement: routes match /api/v1/products
router = DefaultRouter(trailing_slash=False)
```

---

## 4. Inspecting Registered Router URLs

To view every URL pattern generated by your router, inspect `router.urls`:

```python
for url in router.urls:
    print(url.pattern, "──►", url.name)
```

Output:
```
^products/$ ──► product-list
^products/(?P<pk>[^/.]+)/$ ──► product-detail
^categories/$ ──► category-list
^categories/(?P<pk>[^/.]+)/$ ──► category-detail
```

## Practice Quiz

### Q1: What key feature does DefaultRouter include that SimpleRouter lacks?
- A) A built-in database
- B) A default hyperlinked API Root view linking to all registered resources and automated format suffix patterns
- C) SSL certificate verification
- D) Two-factor authentication
**Answer:** B
**Explanation:** DefaultRouter automatically generates a root index view linking to all registered ViewSet resources, whereas SimpleRouter only creates individual resource routes.

### Q2: What happens by default if a client issues a POST request to a Django endpoint without a trailing slash (e.g. /api/products)?
- A) The server returns 500 Internal Server Error
- B) Django issues a 301 redirect to /api/products/, which can cause client HTTP libraries to downgrade the POST to a GET or drop the payload
- C) Django executes the request normally
- D) The database drops the table
**Answer:** B
**Explanation:** Django's default APPEND_SLASH behavior issues a 301 redirect; on POST requests, standard HTTP clients may drop the payload during redirects.

### Q3: How do you configure a DRF router to accept URLs without trailing slashes (e.g. /api/v1/products)?
- A) trailing_slash = False (e.g. DefaultRouter(trailing_slash=False))
- B) APPEND_SLASH = False in urls.py
- C) strip_slashes=True
- D) It cannot be changed
**Answer:** A
**Explanation:** Initializing the router with trailing_slash=False instructs DRF to generate regex patterns without trailing slashes.

### Q4: When calling router.register("items", ItemViewSet, basename="item"), what is the named URL for the detail view?
- A) item-detail
- B) item-get
- C) item_retrieve
- D) item.show
**Answer:** A
**Explanation:** DRF routers standardize names as <basename>-detail for individual items and <basename>-list for collections.

### Q5: Can standard path() routes and router-generated routes coexist in the same urlpatterns list?
- A) No, routers forbid custom paths
- B) Yes, you can combine path("auth/", ...), custom views, and path("", include(router.urls)) in the same urlpatterns array
- C) Only on Linux servers
- D) Only in development mode
**Answer:** B
**Explanation:** router.urls is simply a list of URLPattern objects that can be seamlessly merged with custom path() statements in urlpatterns.
