# Comparing Changes with `git diff` (Working Tree vs Staged vs HEAD)

Before staging or committing code, careful developers verify their exact modifications. The `git diff` command is Git's microscope: it shows line-by-line additions, deletions, and alterations using unified diff format.

---

## 1. The Three Forms of `git diff`

Because Git has three trees (Working Directory, Staging Area, and HEAD Commit), `git diff` provides three primary comparison targets:

```
[ Working Directory ] <====== 1. git diff ==============> [ Staging Area ]
                                                                 ^
                                                                 |
                                                          2. git diff --staged
                                                                 |
                                                                 v
                      <====== 3. git diff HEAD =========> [ HEAD (Last Commit) ]
```

### 1. `git diff` (Working Directory vs. Staging Area)
Shows changes you have made in files that **have NOT yet been staged**:
```bash
git diff
```

### 2. `git diff --staged` (Staging Area vs. Last Commit)
Shows changes that **are currently staged** and ready to be included in the next commit:
```bash
git diff --staged
# Synonym:
git diff --cached
```

### 3. `git diff HEAD` (Working Directory vs. Last Commit)
Shows all changes on your disk (both staged and unstaged combined) compared against the last recorded commit:
```bash
git diff HEAD
```

---

## 2. Reading Unified Diff Syntax

When you run `git diff`, Git outputs unified diff notation:

```diff
diff --git a/src/app.py b/src/app.py
index e69de29..b2d9a10 100644
--- a/src/app.py
+++ b/src/app.py
@@ -10,7 +10,8 @@ def calculate_discount(price, customer_type):
-    if customer_type == "regular":
-        return price * 0.05
+    if customer_type == "vip":
+        return price * 0.20
+    elif customer_type == "regular":
+        return price * 0.10
     return 0
```

### Decoding the Diff:
- `--- a/src/app.py` : Original version before changes (pre-image).
- `+++ b/src/app.py` : Modified version after changes (post-image).
- `@@ -10,7 +10,8 @@` : **Hunk header**. In the original file, chunk begins at line 10 and spans 7 lines; in the new file, chunk begins at line 10 and spans 8 lines.
- `-` (Red) : Removed / deleted lines.
- `+` (Green) : Added / inserted lines.
- White / uncolored text : Unchanged context lines around the modification.

---

## 3. Targeted Diffs

### Compare a Specific File:
```bash
git diff src/components/Button.jsx
```

### Compare Two Different Branches:
See what changes exist in `feature-login` compared to `main`:
```bash
git diff main..feature-login
```

### Compare Two Commits by Hash:
```bash
git diff 3a89e12..7b3f81e
```

### Word-Level Diff (`--word-diff`):
When you change only one word inside a long paragraph, viewing the entire line as deleted and re-added can be noisy:
```bash
git diff --word-diff
```

## Practice Quiz

### Q1: What does running `git diff` without any arguments compare?
- A) Remote GitHub repository vs local hard disk
- B) Working directory modifications vs the Staging Area (index)
- C) Your branch vs the main branch
- D) Two commits from yesterday
**Answer:** B
**Explanation:** `git diff` with no flags compares un-staged changes in the working directory against the current staging area index.

### Q2: Which command shows the exact diff of changes that are already staged and about to be committed?
- A) `git diff --commit`
- B) `git diff --staged` (or `git diff --cached`)
- C) `git diff --all`
- D) `git diff --index`
**Answer:** B
**Explanation:** `git diff --staged` (synonym: `git diff --cached`) displays the difference between the staging area and the last commit (`HEAD`).

### Q3: In a Git diff output, what do lines beginning with a green `+` signify?
- A) Errors detected by the compiler
- B) Lines that were added or newly inserted
- C) Files that were deleted
- D) Comments generated by Git
**Answer:** B
**Explanation:** Lines beginning with `+` in unified diff format represent additions or inserted lines in the new revision.

### Q4: What does `git diff HEAD` display?
- A) Only the commit message of the last commit
- B) All modifications in the working directory (both staged and unstaged) compared against the last commit
- C) CPU load for Git processes
- D) The difference between master and origin/master
**Answer:** B
**Explanation:** `git diff HEAD` compares your current working tree (including anything in the staging area) directly against the latest commit referenced by `HEAD`.

### Q5: How can you view the changes introduced between two branches named `dev` and `main`?
- A) `git compare dev main`
- B) `git diff dev..main`
- C) `git status dev main`
- D) `git show dev main`
**Answer:** B
**Explanation:** `git diff branchA..branchB` shows the line-by-line differences between the tips of the two specified branches.
